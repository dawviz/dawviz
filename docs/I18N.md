# Đa ngôn ngữ (i18n) và đóng góp bản dịch / Localization & translation guide

> **EN** — The UI is translated through plain JSON catalogs in [`locales/`](../locales). English (`en`) is the source; Vietnamese (`vi`) is complete. Anyone can add a language with a pull request — no code changes needed. Run `npm run i18n:check` before opening it.
> **VI** — Giao diện dịch qua các file JSON trong [`locales/`](../locales). Tiếng Anh (`en`) là bản gốc, tiếng Việt (`vi`) đã đủ. Ai cũng có thể thêm ngôn ngữ bằng pull request, không cần sửa mã. Chạy `npm run i18n:check` trước khi gửi.

## 1. Thêm một ngôn ngữ mới (How to add a language)

1. Sao chép `locales/en.json` thành `locales/<mã>.json`. Mã theo BCP 47: `fr`, `es`, `pt-BR`, `zh-Hans`, `ja`, `ar`...
2. Sửa khối `@meta`:
   ```json
   "@meta": { "code": "fr", "name": "Français", "dir": "ltr", "status": "partial", "translators": ["Tên bạn"] }
   ```
   - `name`: tên ngôn ngữ viết **bằng chính ngôn ngữ đó** (hiện trong danh sách chọn).
   - `dir`: `ltr` hoặc `rtl` (Ả Rập, Do Thái, Ba Tư, Urdu: `rtl`).
   - `status`: `partial` khi dịch chưa đủ (khoá thiếu sẽ tự dùng tiếng Anh), đổi thành `complete` khi đã đủ; khi `complete`, thiếu khoá là lỗi.
3. Dịch **giá trị** (bên phải dấu `:`), **không đổi khoá** (bên trái). Khoá chưa dịch có thể xoá đi; đừng để chuỗi rỗng.
4. Thêm một dòng vào `locales/index.json`: `{ "code": "fr", "name": "Français" }`.
5. `npm run i18n:check` (hoặc `node scripts/check-i18n.mjs fr`) rồi mở pull request.

## 2. Cú pháp chuỗi (Message syntax)

| Cú pháp | Ý nghĩa | Ví dụ |
|---|---|---|
| `{tên}` | tham số, **giữ nguyên tên**, chỉ dịch phần chữ xung quanh | `"Xin chào {name}"` |
| `{n, plural, one {# tệp} other {# tệp}}` | số nhiều theo quy tắc của ngôn ngữ (`zero one two few many other`), `#` = số đã định dạng | Nga cần `one few many other`; Việt chỉ cần `other` |
| `=0 {không có}` | nhánh cho đúng một giá trị | `{n, plural, =0 {none} one {# file} other {# files}}` |

- Nhánh `other` luôn bắt buộc. Chỉ dùng các nhánh mà ngôn ngữ của bạn có (bộ kiểm tra báo lỗi nếu dùng nhánh không tồn tại, ví dụ `one` trong tiếng Việt).
- Không đưa HTML hay Markdown vào chuỗi; không ghép câu từ nhiều chuỗi (thứ tự từ mỗi ngôn ngữ một khác).
- Giữ nguyên tên kỹ thuật: `.als`, `.rpp`, `BPM`, `PPQ`, `tick`, tên DAW.

## 3. Nhóm khoá (Key groups)

| Tiền tố | Nội dung |
|---|---|
| `app.*`, `lang.*`, `file.*`, `btn.*`, `opt.*`, `th.*`, `out.*` | nhãn, nút, bảng, kết quả |
| `tempo.*`, `pack.*`, `midi.*`, `schema.*`, `notice.*` | khối ghi đè BPM, chọn `.als` trong `.alp`, thông báo cần thêm file |
| `errors.ERR_*` | thông báo lỗi cho người dùng, theo **mã lỗi** của thư viện |
| `warn.WARN_*` | thông báo cảnh báo, theo **mã cảnh báo** của thư viện |

Thư viện parser trả về `code` + `message`. `message` là chuỗi **kỹ thuật cho nhà phát triển** (hiện bằng tiếng Việt), được giao diện đặt trong mục "chi tiết kỹ thuật"; người dùng đọc bản dịch của `code`. Vì vậy thêm mã lỗi/cảnh báo mới ở thư viện thì phải thêm khoá `errors.*`/`warn.*` tương ứng vào `en.json` và `vi.json`.

## 4. Quy ước cho nhà phát triển (Developer rules)

- Mọi chuỗi hiển thị phải qua `t('khoá', {tham_số})` hoặc thuộc tính `data-i18n="khoá"`; không viết chữ cứng trong HTML/JS. Khoá viết thường, phân cấp bằng dấu chấm: `nhóm.mục`.
- Thêm khoá vào `en.json` **và** `vi.json` cùng lúc. `en.json` là nguồn; mọi khoá mới phải có ở đó.
- Không ghép chuỗi bằng `+`; dùng tham số. Số và thời lượng định dạng bằng `i18n.number()`/`Intl`, không tự thêm dấu phân cách.
- Dùng thuộc tính CSS logic (`margin-inline-start`, `text-align:start`) và `dir` của `<html>` để sẵn sàng cho ngôn ngữ viết từ phải sang trái.
- `npm run i18n:check` kiểm: JSON hợp lệ, `@meta`, đủ khoá (khi `complete`), không khoá thừa, không chuỗi rỗng, tham số khớp bản gốc, nhánh số nhiều hợp lệ, khoá dùng trong mã nguồn đều có trong `en.json`, khoá không còn dùng.
- Chọn ngôn ngữ: lưu lựa chọn người dùng (`localStorage`, có `try/catch`), nếu chưa có thì `navigator.languages` khớp theo chuỗi `vi-VN → vi`, cuối cùng dùng `en`.

## 5. Ngoài chuỗi giao diện (Beyond UI strings)

Các phần sau cũng thuộc phạm vi đa ngôn ngữ của sản phẩm (xem SRS v0.3, REQ-I18N-*), sẽ làm khi có giao diện chính:
- **Văn bản trên canvas và video xuất ra** (Track Info, Chord Detection, tên widget): dùng cùng danh mục; cần font có đủ glyph cho chữ viết đó (CJK, Ả Rập, Thái, Devanagari...), nạp bằng `FontFace` trong Worker xuất video.
- **Cách ghi tên nốt/hợp âm** là một thiết lập riêng, không gắn với ngôn ngữ giao diện: `C D E` (mặc định), `Do Re Mi` (La tinh, Pháp, Ý, Việt...), `H` thay `B` (Đức/Bắc Âu), `ハニホ` (Nhật), tên bậc.
- **Tài liệu**: bản dịch của README và hướng dẫn đặt trong `docs/<mã>/`; bản tiếng Việt và tiếng Anh do nhóm giữ cập nhật.
